# 문제 해결 기록

## 1. secrets.toml 파일 위치가 잘못됨 (2026-11-25)

- **증상:** 테스트 앱 실행 시 "API 키를 찾지 못했습니다" 안내가 뜸.
- **원인:** 키 파일이 `.streamlit/secrets.toml`이 아니라 프로젝트 맨 위에
  `.streamlitsecrets.toml`이라는 이름으로 저장되어 있었다 (폴더 구분자 `/`가 빠짐).
  Streamlit은 `.streamlit` 폴더 안의 `secrets.toml`만 읽는다.
- **해결:** 파일을 `.streamlit/secrets.toml`로 옮겼다. 키가 실수로 커밋되지 않도록
  `.gitignore`에 두 이름을 모두 적고, `git check-ignore -v`로 제외 여부를 확인했다.
- **결과:** 옮긴 뒤 "API 키를 불러왔습니다"가 표시되고, 서울대입구역 → 강남역 조회가
  정상 동작했다 (14분, 환승 0회, 1,550원, SUBWAY, 경로 14개 중 최단).

## 2. 공공데이터 역 좌표 오류 (2026-11-25)

- **증상:** 전처리 중 "같은 노선에서 50m 안에 붙어 있는 서로 다른 역"을 찾아보니
  5호선 마곡–발산(7m), 4호선 신용산–이촌(14m)이 나왔다. 실제로는 각각 약 1km 떨어진 역이다.
- **원인:** 원본(국가철도공단 역사정보)에서 마곡에 발산의 좌표, 이촌에 신용산의 좌표가 잘못 들어가 있었다.
- **해결:** 한국어 위키백과의 좌표로 교체하고, `prepare_data.py`의 `FIX_COORDS`에 출처와 함께 적었다.
  (카카오 API 결과는 파일로 저장하면 안 되므로 카카오로 고치지 않았다.)

## 3. 같은 역인데 이름이 달라 합쳐지지 않음 / 다른 역인데 이름이 같음 (2026-11-25)

- **증상:** 환승역을 이름으로 합쳤더니 "신도림"과 "신도림역"이 따로 남았다.
  또 "역"을 떼고 나니 5호선 양평(서울)과 경의중앙선 양평(양평군, 약 54km 거리)이 한 역으로 합쳐질 뻔했다.
- **원인:** 한국철도공사 노선은 역 이름 뒤에 '역'이 붙어 있다. 7호선 '이수'와 4호선 '총신대입구(이수)'처럼
  노선마다 이름이 다른 역도 있다.
- **해결:** 괄호와 끝의 '역'을 떼고, 별칭은 `NAME_ALIASES`로 통일했다.
  이름이 같아도 1km 넘게 떨어지면 `양평(경의중앙선)`처럼 노선 이름을 붙여 다른 역으로 구분했다.

## 4. 경의중앙선 역이 '1호선'으로 표시됨 (2026-11-25)

- **증상:** 이촌·서빙고·왕십리 등이 "1호선"으로 표시되었다.
- **원인:** 원본은 노선을 선로 기준(경원선)으로 적는데, 경원선 용산~왕십리 구간(역번호 1003~1013)에는
  실제로 경의중앙선 전철이 다닌다.
- **해결:** `fix_gyeongwon_line()`에서 이 구간만 경의중앙선으로 바꾼 뒤 나머지 경원선을 1호선으로 바꿨다.

## 5. 다른 페이지에 다녀오면 입력값이 사라짐 (2026-11-25)

- **증상:** Streamlit 여러 페이지 앱에서 다른 페이지로 갔다가 돌아오면 입력칸(위젯) 값이 기본값으로 돌아간다.
- **원인:** Streamlit은 화면에 그려지지 않은 위젯의 값을 session_state에서 지운다.
- **해결:** 위젯 키는 `_name_0`처럼 밑줄을 붙여 쓰고, 값이 바뀔 때(`on_change`) 밑줄 없는 키 `name_0`에 복사해 둔다.
  페이지를 다시 열면 `prepare()` 함수가 저장된 값을 위젯 키에 다시 넣어 준다.
  다른 페이지에 다녀와도 이름·출발지·기준·확정한 역이 그대로 남는 것을 브라우저에서 확인했다.

## 6. 데모 모드·카카오 검색 실패 시 출발지를 입력할 수 없음 (2026-11-25)

- **증상:** 데모 모드는 API를 부르지 않으므로 카카오 키워드 검색도 쓸 수 없어 출발지를 고를 방법이 없다.
- **해결:** `stations.csv`에서 역 이름으로 찾는 `search_stations()`를 만들어, 데모 모드이거나 카카오 검색이 실패하면
  대신 쓰도록 했다. (검색 결과 아래에 어떤 방식으로 찾았는지 안내 문구 표시)

## 7. 주변 장소가 15곳만 나와 반경을 넓혀도 결과가 같음 (2026-11-25)

- **증상:** 반경을 300m에서 1000m로 넓혀도 같은 15곳이 나왔다. (신당역 카페 15곳이 모두 150m 안)
- **원인:** 카카오 장소 검색은 한 번에 최대 15곳만 돌려준다.
- **해결:** `page` 파라미터로 최대 3페이지(45곳)까지 이어서 받는다. 응답의 `meta.is_end`가 True면 멈춘다.

## 8. 메뉴 키워드 검색에 관련 없는 가게가 먼저 나옴 (2026-11-25)

- **증상:** 강남역 주변 '파스타'를 거리순(`sort=distance`)으로 검색하니 아시아음식점·빵집·와인바가 맨 앞에 나왔다.
- **원인:** 키워드 검색은 이름·메뉴 등에 단어가 조금만 걸려도 결과에 포함되는데, 거리순이면 관련도와 상관없이 가까운 곳이 앞에 온다.
  관련도순(`accuracy`)으로 45곳을 받은 뒤 거리순으로 다시 정렬하는 방법도 시도했지만, 45곳 안에도 관련 적은 곳이 섞여 있어 같은 문제가 생겼다.
- **해결:** 키워드 검색은 관련도순을 그대로 보여주고, 표에 거리 열을 두어 필요하면 열 이름을 눌러 거리순으로 볼 수 있게 했다.
  ('삼겹살' 관련도순 상위 결과가 모두 삼겹살 전문점인 것을 확인)

## 9. 정산 표(st.data_editor) 입력이 페이지 이동 후 사라짐 (2026-11-25)

- **증상:** 정산 표에 금액을 적고 다른 페이지에 다녀오면 표가 처음 상태로 돌아간다.
- **원인:** `st.data_editor`는 원본 표가 아니라 "바뀐 부분"만 위젯 상태로 기억하는데, 다른 페이지로 가면 이 위젯 상태가 지워진다.
- **해결:** 매번 편집 결과 표를 `settle_saved`에 저장하고, 페이지에 새로 들어왔을 때(편집기 상태가 없을 때)만
  저장된 표를 시작 값으로 쓰도록 했다. 같은 페이지 안에서 시작 값을 계속 바꾸면 편집 내용이 이중으로 적용되므로 주의.

## 10. 화면 문구가 글머리 기호로 바뀜 (2026-11-25)

- **증상:** `st.caption("+ 는 돌려받을 돈 ...")`이 "• 는 돌려받을 돈"처럼 목록으로 표시되었다.
- **원인:** Streamlit 문구는 마크다운으로 해석되는데, 줄 맨 앞의 `+ `는 마크다운에서 목록 기호다.
- **해결:** 문장을 "잔액 = 낸 돈 − 1인당 금액. 양수(+)는 ..."처럼 `+`로 시작하지 않게 바꿨다.

## 11. 해석 문구가 비교표와 다른 역을 가리킴 (2026-11-25)

- **증상:** 분석 실험실 비교표에서는 배려형 1위가 행당역인데, 산점도 해석 문구는 "최장이 가장 작은 곳은 동대문역사문화공원역"이라고 했다.
- **원인:** 두 역의 최장 이동시간이 43분으로 같았다. 해석 문구는 `idxmin()`(같은 값이면 먼저 나온 역)을 썼고,
  비교표는 `score_stations()`(같은 점수면 최장 → 총합 순으로 정렬)를 써서 동점 처리 방식이 달랐다.
- **해결:** 해석 문구도 `score_stations()`의 1위를 쓰도록 바꿔 화면 전체에서 같은 동점 규칙을 쓰게 했다.
  (AppTest로 화면 문구를 자동으로 읽어 보다가 발견)
